# 0019 — Café-derived Shopping jobs and private receipt photos

Accepted November 7, 2026 for issue #47.

The owner requested a Shopping job restricted to café workers and fast receipt-photo capture with either password or PIN, followed by in-app administrator/manager review, archive, deletion and photo export. Receipt handling must not disturb clocking or grant financial/administrative authority.

Use an explicit organization-specific mapping from an existing café job to a regular Shopping job in the same community. Materialize its derived membership in the existing `user_jobs` model for compatibility with clocking, schedules, time-card editors, reports and payroll job identity. Normalize every staff write/import and enforce final membership closure with deferred constraints. Keep inactive derived grants latent so archiving/restoring the job does not require another bulk assignment operation. Provision the first mapping and existing memberships through a reviewed idempotent operator function after the new web source is live. The web role cannot provision mappings or run migrations.

Store bounded, normalized private photos and thumbnails in PostgreSQL with receipt metadata, immutable lifecycle events and minimal exact-retry command receipts. This uses existing durable infrastructure/backups without introducing public object URLs, deployment-local file loss, new credentials or the paused finance attachment work. A logical quota, bounded parser/decoder admission and metadata-only list reads contain storage/CPU/memory impact. JPEG normalization removes metadata and avoids serving untrusted input formats. Future object-storage migration requires a separate reviewed design and retained authorization behavior.

Use current server-verified password/PIN sessions for own capture/history. PIN grants no team/report/lifecycle access, regardless of the account role. Password reporting roles read in existing organization/community scope; managers/developer/owner/administrator manage in current scope directly, including own receipts. Current account locks, membership/job locks, session/MFA proof, transaction retries, expected versions and atomic audit/event/command writes remain mandatory. Images never enter command or audit JSON. Deletion removes live photo/purchase content, retains audit tombstones and is explicit about separate backup retention.

The workspace owns the receipt draft and captured in-flight command across page navigation. It can minimize without blocking time-clock transitions, while reload/update/sign-out guards expose unresolved local work. No offline persistence/background upload, OCR, purchasing approval, reimbursement, ledger posting, wage policy or school-record integration is included. Photos can be added off-clock; optional time-card links capture the current revision and never mutate time.
